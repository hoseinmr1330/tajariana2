# تاج آریانا — پروژهٔ بازی اندروید

**ژانر:** استراتژی قرون‌وسطایی، ساخت قلمرو، اقتصاد، ارتش و دیپلماسی  
**موتور:** Godot 4.7.2  
**جهت صفحه:** افقی (Landscape)  
**زبان رابط:** فارسی  
**نوع نسخه:** نمونهٔ اولیهٔ قابل‌بازی، آفلاین و تک‌نفره

این پروژه یک بازی مستقل با الهام از ساختار بازی‌های استراتژی موبایلی مانند *Clash of Empire* است. نام، کد، نقشه، رابط و تصاویر ساختمان‌ها برای این پروژه ساخته شده‌اند؛ فایل‌ها و تصاویر اختصاصی بازی مرجع در آن استفاده نشده‌اند.

## اصلاحیهٔ نسخهٔ 0.1.4

در نسخهٔ 0.1.4، جهت نمایش در هر دو تنظیم پروژه و Android روی Landscape تنظیم شده است. گزینهٔ ETC2/ASTC در بخش `[rendering]` فعال است؛ GitHub Actions قبل از Import آن را تضمین می‌کند، پوشهٔ `.godot` را پاک می‌کند تا بافت‌ها از نو وارد شوند، مقدار بارگذاری‌شده را از خود Godot می‌خواند، تمام تصاویر و صحنهٔ اصلی را بارگذاری و instantiate می‌کند و سپس APK را می‌سازد. One-click Deploy خاموش است؛ ساخت APK به اتصال گوشی یا شبیه‌ساز نیاز ندارد.

## چه چیزهایی در این نسخه کار می‌کنند؟

- نمایش شهر ایزومتریک با شش ساختمان تصویری: قلعه، سربازخانه، مزرعه، کارگاه چوب‌بری، معدن سنگ و معدن طلا.
- انتخاب ساختمان و ارتقای سطح آن با پرداخت طلا، چوب و سنگ.
- تولید دوره‌ای منابع در پس‌زمینهٔ بازی.
- آموزش شمشیرزن، کماندار و سواره‌نظام.
- نقشهٔ قلمرو و سه مأموریت حمله به اردوگاه/دژ.
- محاسبهٔ نتیجهٔ نبرد بر اساس قدرت سپاه و کاهش نیروها.
- سه شاخهٔ فناوری: نظامی، کشاورزی و مهندسی.
- تجارت و بهبود رابطه با پادشاهی‌های همسایه.
- ذخیره و بارگذاری خودکار پیشرفت در حافظهٔ محلی برنامه.
- گردش صفحات با دکمه‌های لمسی.


### نکته مهم درباره ساختار مخزن

فایل `project.godot` باید مستقیماً در ریشه مخزن GitHub باشد و پوشه‌های `scenes`، `scripts`، `assets` و `.github` نیز کنار آن قرار بگیرند. پوشه مادر `Taj_Ariana_Godot_Source` را داخل مخزن قرار ندهید؛ محتویات آن را بارگذاری کنید.

برای ساخت APK هیچ گوشی یا شبیه‌سازی لازم نیست. Workflow سرویس محلی ADB را فقط برای حذف پیام اتصال به daemon راه‌اندازی می‌کند؛ از ADB برای نصب یا اجرای بازی استفاده نمی‌کند.

## ساخت APK با GitHub (بدون نصب Godot روی رایانه)

1. فایل ZIP نسخهٔ 0.1.4 را از حالت فشرده خارج کنید.
2. در GitHub یک مخزن جدید بسازید. برای شروع می‌توانید مخزن را **Public** بگذارید تا محدودیت دقیقه‌های Actions کمتر دردسرساز شود.
3. تمام محتویات پوشهٔ `Taj_Ariana_Godot_Source` را در ریشهٔ مخزن بارگذاری کنید؛ یعنی `project.godot` باید مستقیماً در ریشه باشد، نه داخل یک پوشهٔ اضافی.
4. وارد تب **Actions** مخزن شوید.
5. گردش‌کار **Build Android APK** را انتخاب کنید و روی **Run workflow** بزنید. با هر Push به شاخهٔ `main` یا `master` نیز به‌طور خودکار اجرا می‌شود.
6. بعد از پایان موفق کار، وارد همان اجرای Workflow شوید و از قسمت **Artifacts** فایل `Taj-Ariana-Android-APK` را دانلود کنید.
7. ZIP دانلودشده را باز کنید و فایل `TajAriana.apk` را روی گوشی نصب کنید. ممکن است اندروید اجازهٔ نصب از منبع ناشناس را بخواهد.

### نکات مهم دربارهٔ APK

- این Workflow یک **Debug APK** قابل نصب برای آزمایش و نصب مستقیم می‌سازد؛ برای انتشار عمومی در فروشگاه، باید نسخهٔ Release را با کلید امضای اختصاصی خودتان بسازید.
- خروجی فعلی ARMv7 و ARM64 را فعال می‌کند تا روی طیف وسیع‌تری از گوشی‌ها نصب شود.
- فایل APK داخل بخش Artifacts اجرای GitHub Actions قرار می‌گیرد؛ در مخزن به‌صورت خودکار Commit نمی‌شود.
- ساخت APK نیازمند دریافت Godot، Export Templates و Android SDK در محیط GitHub است؛ Workflow تمام این مراحل را خودکار انجام می‌دهد.

## اجرای بازی روی رایانه

1. Godot **4.7.2 Standard** را از وب‌سایت رسمی دریافت کنید.
2. پروژه را با گزینهٔ **Import** باز کنید و فایل `project.godot` را انتخاب کنید.
3. صحنهٔ اصلی `scenes/main.tscn` است؛ دکمهٔ Play را بزنید.

## محدودیت‌های صریح نسخهٔ اول

این نسخه یک بازی آفلاین تک‌نفره است. هنوز سرور آنلاین، حساب کاربری، اتحادهای چندنفره، چت واقعی، PvP هم‌زمان، خرید درون‌برنامه‌ای، تایمرهای واقعی ساخت در پس‌زمینه، انیمیشن مستقل نبرد و سیستم قهرمانان قابل ارتقا ندارد. این موارد نیازمند طراحی و پیاده‌سازی مرحلهٔ بعد و برای بخش آنلاین نیازمند بک‌اند و میزبانی سرور هستند.

## حریم داده

پیشرفت فقط در فضای ذخیره‌سازی خصوصی همان نصب برنامه ذخیره می‌شود و هیچ داده‌ای به سرور ارسال نمی‌شود. حذف داده‌های برنامه یا پاک کردن حافظهٔ آن، ذخیرهٔ محلی را پاک می‌کند.


### بررسی ETC2/ASTC و سلامت پروژه در نسخهٔ 0.1.4

کلید `textures/vram_compression/import_etc2_astc=true` زیر بخش `[rendering]` در `project.godot` قرار دارد؛ این قالب صحیح ذخیره‌سازی تنظیمات Godot است. Workflow علاوه بر تضمین‌کردن این مقدار، کل پوشهٔ `.godot` را پاک می‌کند تا Import از صفر انجام شود. سپس اسکریپت `scripts/ci_validate.gd` مقدار واقعی بارگذاری‌شده را از `ProjectSettings` می‌خواند، همهٔ تصاویر را load می‌کند، صحنهٔ اصلی را instantiate می‌کند، تمام صفحه‌ها را می‌سازد و پنجرهٔ جزئیات ساختمان را باز و بسته می‌کند. در صورت شکست هر بررسی، مرحلهٔ Export اجرا نمی‌شود.

برای جزئیات اصلاحات این نسخه، فایل `CHANGELOG_0.1.4_FA.md` را ببینید.


## اصلاحات نسخه 0.1.5 و ساخت APK

در Workflow اندروید، پیش از واردسازی تصاویر، اسکریپت `scripts/ci_prepare.gd` مقدار `rendering/textures/vram_compression/import_etc2_astc` را با `ConfigFile` در بخش `[rendering]` فایل `project.godot` می‌نویسد، دوباره می‌خواند و مقدار زندهٔ `ProjectSettings` را نیز بررسی می‌کند. سپس `.godot` پاک و واردسازی تازه انجام می‌شود. اعتبارسنجی بعدی هم مقدار ذخیره‌شده و مقدار بارگذاری‌شده را جداگانه کنترل می‌کند.

دو خطای نوع‌دهی GDScript که در گزارش CI نسخه 0.1.4 دیده شده بود نیز رفع شده‌اند: مقدار `active` به `bool` و ضریب `discount` به `float` نوع‌دهی صریح شده و از `maxf()` استفاده می‌شود.

برای ساخت در GitHub، همه فایل‌های اصلاحیه را با حفظ مسیرها در ریشه مخزن جایگزین کنید؛ سپس از Actions، گردش‌کار `Build Android APK` را اجرا کنید. دیگر نیازی به اجرای ADB یا اتصال گوشی برای ساخت APK نیست.
